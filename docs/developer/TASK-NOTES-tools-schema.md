# Tools — schema extensions

Two extensions to the `tools` and `parent_tools` schema defined in `docs/developer/2026-05-03-C-conversation-tools/design.md` "On-disk schema". Both items wait for a concrete tool that needs them.

- **Subtractive directive (`tools_remove`)**: a level may want to inherit most of the chain but drop a single inherited name. The v1 schema offers only `Extend` (append) and `Replace` (clobber). A `tools_remove = ["foo"]` field at any level would remove matching names from the running set before applying the level's own `tools`. Defer until a real workflow demonstrates the need. Today, `Replace` followed by an explicit re-listing covers the common case.
- **Tool argument configuration**: the v1 registry is name-keyed only. Some tools need configuration at registration time (for example a `shell` tool with a per-conversation `cwd`, or a file reader with a path allow-list). Two schema shapes are open. A list-of-tables `[[tools]] name = "shell" args = { cwd = "..." }` replaces the simple list-of-strings. A parallel `[tools.args]` table keyed by name leaves the existing `tools = [...]` shape intact. The on-disk schema's list-of-strings shape leaves room to switch to a list-of-tables in the future without breaking unparameterized consumers, since `toml` permits both shapes if the parser handles them. The registry trait, or a richer registry trait, carries the args at resolution time.

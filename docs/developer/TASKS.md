- **template variables in prefix/turn contents** — Today [DESIGN.md](../../DESIGN.md) templates only `path?` with matrix variables (the `PrefixBlock.path` and user-turn `TurnTemplate.path` lines); file *contents* are concatenated verbatim. A prompt authored with `{{var}}` placeholders — e.g. an externally-hosted system prompt carrying `{{currentDate}}` / `{{readOnlyInstructions}}` — cannot be filled by Ailly, so a harness must pre-render it outside the tool. Add a content-templating mechanism: fill `{{var}}` inside prefix-block and turn contents from a values source (an assembly-level `vars:` map, the per-binding matrix values, and/or `--var`), with an explicit choice on un-provided placeholders (leave verbatim vs error) and on delimiter collision with the existing `{{ matrix }}` path syntax. This lets an assembly reference a source prompt file directly and lets a variable like read-only mode become a clean matrix axis. **Motivating case:** the Scout Ailly prompt-eval framework (Scout repo `.ailly/developer/2026-06-08-A-prompt-eval/design.md`) first hit this — its Analyst prompt carried `{{currentDate}}`/`{{readOnlyInstructions}}` — but sidestepped it by dropping those (unused) variables and referencing the prompt directly with `kind: external`. The gap remains for any harness whose referenced prompt carries *meaningful* placeholders that must be filled at assemble time. **Trigger:** a harness needs Ailly to fill placeholders inside a referenced prompt file.

- **serde-saphyr for block-by-default emission (incl. tabs)** — `ailly run` now normalizes content on write so `serde_yaml_ng` emits multiline assistant bodies as `|` block scalars ([`fill_blank_assistant`](../../src/content/conversation.rs), `normalize_block_text`): CRLF→LF and trailing spaces/tabs stripped before each line break. libyaml refuses block style for any string containing a tab, so a (rare) tab-containing response still serializes quoted, with the tab preserved losslessly. The maintained pure-Rust line solves this without that conservatism: `saphyr` / `yaml-rust2` `YamlEmitter::multiline_strings(true)` (its `is_valid_literal_block_scalar` gate accepts tabs and trailing spaces, rejects only `\r`), and `serde-saphyr` emits block scalars by default with `LitStr`/`FoldStr` overrides. Either route — keep `serde_yaml_ng` for parse and convert to a saphyr AST for emit, or adopt `serde-saphyr` outright — would also put tabbed content into blocks (losslessly). Deferred now because `serde-saphyr` is v0.0.x with churning `#[non_exhaustive]` APIs and would introduce a second YAML library alongside `serde_yaml_ng`. **Trigger:** tabbed assistant content becomes common, or block-by-default emission is wanted across the data model. - **standalone / ad-hoc eval over a static document** — The eval loop ([src/knowledge/eval.rs](../../src/knowledge/eval.rs), [src/cli/eval.rs](../../src/cli/eval.rs)) is conversation-centric: every assertion family extracts from a `Conversation` (`final_assistant_text()`, the tool_use walk, inline `Trace`), so a target that is *not* the output of `ailly run` — a hand-written markdown paper, a vendored doc, a spec under review — cannot be evaluated without first wrapping it in a synthetic conversation. Today the only bridge is to hand-author a conversation file that parks the document in a single assistant turn (so `judge`/`text_*` see it) or to use a `program`/`script` assertion that reads the file off disk itself (ignoring the conversation entirely). Add first-class support for evaluating a standalone artifact: e.g. `ailly eval <suite> --over <file.md>` (or a `--document`/`--artifact` flag) that lifts an arbitrary text/markdown file into the slot the conversation-centric assertions read, so `judge`, `text_*`, and `script` assertions apply to it directly without a hand-built wrapper or an assembly round-trip. Decide the lift shape (synthetic one-turn conversation vs a new non-conversation eval target), how `when:`/matrix matching degrades when there is no `meta.binding`, and what `tokens`/`latency_ms`/tool-call assertions do against a document that has no trace (skip vs malform). **Motivating case:** the manifold-paper project (relocated to the `davidsouther/resume` repo: paper at `llm_manifold/paper.md`, eval at `llm_manifold/evals/`) needs an Ailly eval whose target is a static `.md` paper (required sections, citation format, a judged claim ledger), not a `run` artifact — and currently hand-builds a conversation bridge in lieu of this feature. **Trigger:** a harness needs to eval a document that was authored by hand rather than produced by `ailly run`. **Research + design drafted (2026-06-26, quick-loop)** at [docs/developer/2026-06-26-A-eval-static-doc/](2026-06-26-A-eval-static-doc/): the feature reduces to one synthetic `(PathBuf, Conversation)` built in `cli::eval::run` when `--over` is a file (the dir-only `VfsConversationRepository` already errors on a single-file root, so the lift must intercept *before* it), handed to the unchanged `evaluate()`. Feature test [tests/eval_static_document.rs](../../tests/eval_static_document.rs) (`eval_over_static_document_scores_assertions_against_its_contents`) is RED. **Next:** clear the `*Draft*` marker on [design.md](2026-06-26-A-eval-static-doc/design.md), then run `developer:plan`.
